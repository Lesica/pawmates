# Связь с реальным миром

Документ от 8 мая 2026. Идея от Алёны: подтянуть **реальную** погоду и время игрока, чтобы виртуальная комната **синхронизировалась** с тем что у игрока за окном.

---

## Главный принцип

**Не приборы и циферки, а сцена и поведение зверя.**

Цифры на экране (температура 18°C, давление 760 мм) превращают cozy-комнату в **дашборд** и убивают атмосферу. Вместо этого — погода и время **проявляются** в:

1. **Состоянии комнаты** (что видно за окном, освещение, штора колышется)
2. **Поведении зверя** (где сидит, какая поза, что делает)

Это даёт переживание «комната живёт со мной в реальном времени», без визуального шума.

---

## Что подтягиваем извне

### Время

Уже есть — через `Date.getHours()` локального времени. Меняет картинку комнаты по 5 режимам (утро/день/вечер/сумерки/ночь). Это работает без backend и без интернета.

### Погода

API: **OpenWeatherMap** (бесплатный tier — 60 запросов/мин, нам хватает с огромным запасом).

Получаем:
- `weather.main`: Clear / Clouds / Rain / Snow / Thunderstorm / Mist / Fog
- `temperature` (для логики реакции зверя, не для показа)
- `wind` (опционально — для шевеления шторы)
- `forecast on hour ahead` (для «зверь чует приближение грозы»)

### Геолокация — **выбор игрока**, не автомат

Два варианта:

- **По IP** (через тот же API): грубо, до города. Privacy-friendly. Но автоматически без согласия — это «втихаря».
- **Через браузер** (`navigator.geolocation`): точно, но требует privacy-prompt — многие отказывают.

**Лучшее решение:** при первом запуске спросить мягко:

> «Из какого города показывать погоду? [определить автоматически] [выбрать вручную]»

Игрок сам решает. Если вручную — даём поиск (`Москва`, `Nha Trang`, `Berlin`). Сохраняем выбор в localStorage.

### Backend обязателен

API-ключ OpenWeatherMap **нельзя** держать в HTML/JS клиента — украдут. Нужен прокси-сервер.

**Дешёвое решение:** Cloudflare Workers (бесплатно до 100k запросов/день). Один маленький endpoint `/weather?city=X` который проксирует к OpenWeatherMap с нашим ключом. Несколько строк кода.

## Как это видно игроку

### За окном (в окне комнаты)

- **Clear** (ясно): голубое небо, лёгкие облака, солнечный луч на полу
- **Clouds** (облачно): серое небо, рассеянный свет, тени мягкие
- **Rain** (дождь): капли стекают по стеклу, штора в полусумраке, пятно света тусклое
- **Snow** (снег): снежинки за окном, на подоконнике лёгкая шапочка снега, освещение приглушённое
- **Thunderstorm** (гроза): тёмное небо, изредка вспышки молний, штора колышется
- **Mist/Fog** (туман): за окном размытость, свет приглушённый
- **Сильный ветер**: штора заметно колышется

### Поведение зверя

Это **сильнее** чем декор окна. Зверь **реагирует**:

| Погода | Поведение зверя |
|---|---|
| Ясно, тепло | Лежит в световом пятне, греется, подбрасывает живот к свету |
| Облачно | Обычная idle-поза, спокойный |
| Дождь | Сидит у окна, смотрит на капли, иногда мяукает беззвучно |
| Снег | Подходит близко к окну, заворожённо смотрит |
| Гроза | Прячется под кресло или у двери, уши вниз |
| Туман | Спокоен, может задремать |
| Очень холодно (за окном <0°C) | Свернулся в клубок, плотно прижавшись к телу |
| Очень жарко (за окном >30°C) | Развалился на боку, лапы в стороны, рот чуть приоткрыт |

Игрок **видит** что котик прячется → выглядывает в окно → «и правда гроза». Это **переживание**, не данные.

### Предсказание (forecast)

API даёт прогноз на час. Это позволяет:

- **«Котик чует»** — за 30-60 минут до грозы котик начинает беспокойно ходить, оглядываться. За 15 минут до дождя — сидит у окна, смотрит вверх.
- Игрок не знает что **именно** будет — но видит что котик «знает что-то». Если сбылось — ощущение магии. Если не сбылось — котик просто странный, и это тоже мило.

Это даёт **anticipation loop**: «интересно что котик чует сегодня».

## Предметы — собираемые, не покупаемые

Если хочется **функциональных** предметов в комнате (барометр, лунный календарь, гигрометр) — они **появляются** не из магазина, а **собираются из подарков** котика.

Пример сборки:
- **Барометр старинный**: ртуть (камешек) + стекляшка + дощечка + стрелочка → собирается на 4-й находке. Появляется на стене. При тапе — короткое объяснение: «давление падает, к дождю».
- **Лунный календарь**: серебряный кругляшок + перо + чёрный камень → появляется на полке. Показывает фазу луны.
- **Барометр-кошка** (керамическая фигурка которая меняет цвет с влажностью): кусочек керамики + два разных цветных порошка → синяя при сухости, розовая при влажности.

Это **встраивает** функциональные штуки в эмоциональную ткань игры. Игрок не **купил** барометр — он **собрал** его из подарков любимого зверя. Эмоциональная стоимость = бабушкина фотография, а не IKEA-полка.

И **не больше 2-3 предметов одновременно** — иначе комната превращается в музей метеорологии. Cozy умирает.

---

## Что НЕ делать

- **Не показывать цифры** на экране (температура, давление, влажность). Никогда.
- **Не делать виджет погоды** в углу. Это иммерсию ломает.
- **Не пушить уведомления** «скоро дождь!». Cozy не работает через push.
- **Не делать барометр / градусник «всегда есть»** — собирать через подарки.
- **Не лезть с геолокацией без согласия.** При первом запуске — мягкий вопрос.
- **Не более 2-3 функциональных предметов** в комнате одновременно.

## Сложность реализации

**Базовый уровень (только смена картинки окна по погоде):**
- Backend на Cloudflare Workers — несколько часов
- Получение погоды + геолокация — час
- Логика смены состояния окна по `weather.main` — час
- Один день работы

**Средний (поведение зверя меняется по погоде):**
- + Новые позы для зверя (5-7 штук): «у окна», «прячется», «развалился», «в клубок», «беспокойный»
- Каждая поза = отдельный SVG, час-два работы каждая
- Логика выбора позы по контексту
- Неделя работы

**Полный (предметы-сборки + предсказание):**
- + Система сборки предметов из подарков
- + Логика «котик чует приближение»
- + UI для разбора собранного
- 2-3 недели работы

## Когда делать

**Не сейчас.** Это **этап 3-4** проекта (после базовой стартовой комнаты + Bond + первых подарков).

Закладываем как **запланированное** будущее. Когда стартовая комната будет полноценной с подарками и Bond — добавляем backend, погоду, реакции зверя. Тогда **wow-эффект** будет сильнее, потому что игрок уже привязан к зверю.

---

## Этический момент

Геолокация — **чувствительные данные**. Алёнин совет: «спросить мягко, дать выбор» — это правильно.

Дополнительно:
- Хранить локацию **только локально** (localStorage), не отправлять на наш сервер.
- Backend получает погоду по **городу** (название), не по точным координатам.
- Игрок может изменить или удалить выбор города в настройках.

Это **уважение к игроку**. Cozy-аудитория особенно ценит этот подход.
